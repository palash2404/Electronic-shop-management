Electronics knowledge graph

A learning project that takes a small electronics shop database and grows it into a validated knowledge graph with an AI assistant on top. The shop is reframed around circular economy: products are made of components, components contain materials, and some materials are hazardous.

1

Data sources

The current repo only creates a registration table; the customer, product, bill and sales tables are used in code but never defined. Finish the relational schema first and add the circular economy tables, so the graph has real connections to work with.

Tools

  • MySQL, schema.sql
  • Python seed script

You learn

  • Why flat tables hide relationships
  • What a good domain model looks like

New tables: component, material, manufacturer, plus link tables product_component and component_material (with mass in grams).

Done when about 20 real products (phones, laptops, chargers) are seeded with their components and materials.

2

OWL ontology

The ontology is the vocabulary and rulebook for the graph: which kinds of things exist and how they may connect. It is a schema, not a visualization; you view it in Protégé or WebVOWL.

Tools

  • Protégé (desktop editor)
  • HermiT reasoner
  • WebVOWL for the picture

You learn

  • Classes, subclasses, properties
  • Domain and range
  • Inference: facts you never wrote
:Smartphone  rdfs:subClassOf :Device .
:hasPart     a owl:TransitiveProperty .
:HazardousProduct owl:equivalentClass [
    owl:onProperty :hasPart ;
    owl:someValuesFrom [ owl:onProperty :containsMaterial ;
                         owl:someValuesFrom :HazardousMaterial ] ] .

Done when ontology.ttl exists and the reasoner classifies a phone with a lead-containing solder joint as a HazardousProduct on its own.

3

RDF graph and SPARQL

A Python script reads MySQL and writes every row as triples using the ontology's terms. SPARQL then answers the analysis questions.

Tools

  • rdflib
  • Turtle (.ttl) files
  • Apache Jena Fuseki (optional)

You learn

  • URIs, triples, namespaces
  • SPARQL SELECT, FILTER, GROUP BY
  • Property paths like :hasPart+
# Products sold last month that contain a hazardous material
SELECT ?product (SUM(?qty) AS ?sold) WHERE {
  ?sale :ofProduct ?product ; :quantity ?qty ; :date ?d .
  ?product :hasPart+/:containsMaterial ?m .
  ?m a :HazardousMaterial .
  FILTER (?d >= "2026-10-01"^^xsd:date)
} GROUP BY ?product ORDER BY DESC(?sold)

Done when to_rdf.py produces data.ttl and five saved queries return correct answers.

4

SHACL validation

SHACL shapes describe what valid data looks like. Every load, and later every AI write, passes through this gate. Failures go to a readable error report instead of the database.

Tools

  • pyshacl
  • shapes.ttl

You learn

  • Node and property shapes
  • Cardinality, datatypes, value ranges
  • How SHACL differs from OWL
:ProductShape a sh:NodeShape ;
  sh:targetClass :Product ;
  sh:property [ sh:path :price ; sh:datatype xsd:decimal ;
                sh:minInclusive 0 ; sh:minCount 1 ; sh:maxCount 1 ] ;
  sh:property [ sh:path :hasPart ; sh:class :Component ; sh:minCount 1 ] .

Done when you break the data on purpose (negative price, product with no parts) and the report names each problem.

5

Neo4j and Cypher

RDF and Neo4j use different graph models. Rather than syncing two databases, the neosemantics plugin imports the validated RDF into Neo4j, which becomes the working store for the agent.

Tools

  • Neo4j in Docker
  • neosemantics (n10s) plugin
  • Neo4j Browser and Bloom

You learn

  • Labeled property graphs
  • Cypher MATCH, CREATE, MERGE
  • RDF vs property graph trade-offs
MATCH (p:Product)-[:HAS_PART*]->(:Component)-[:CONTAINS]->(m:Material {hazardous:true})
RETURN p.name, collect(DISTINCT m.name) AS hazards

Done when all five SPARQL queries are rewritten in Cypher with the same results, and Bloom shows the product graph.

6

AI agent

A PydanticAI agent with typed tools. The model never writes raw Cypher for changes: it calls a tool, the tool builds the triples, SHACL checks them, and only then does Neo4j get updated. A small, cheap model is enough because the tools do the heavy lifting.

Tools

  • PydanticAI
  • Small hosted model or local Ollama
  • Langfuse for traces

You learn

  • Tool calling with typed inputs
  • Guardrails on writes
  • Tracing what the model did

Starter tools: search_products, get_hazards, run_readonly_cypher, add_product, update_product, delete_product (asks for confirmation).

Done when “add a 65W USB-C charger with a lithium battery” creates valid nodes, and “set its price to -5” is refused with the SHACL reason.

7

Extraction and evaluation

An extraction tool reads a product datasheet or safety data sheet (PDF) and turns it into components and materials. A small Langfuse dataset checks that answers stay correct as you change things.

Tools

  • pypdf or pdfplumber
  • Pydantic output models
  • Langfuse datasets and scores

You learn

  • Structured extraction
  • Evaluating LLM output
  • Regression testing an agent

Done when three real datasheets import cleanly and a 10-question eval set scores every run in Langfuse.
