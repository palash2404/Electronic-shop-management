Check yourself before bed

Write your answers in NOTES.md in the repo first, then open each one to compare. We go through them at the start of day 2.

1. Why does a many-to-many relationship need a link table in SQL? What replaces it in RDF?

A table column holds one value per row, so a product cannot list many components in one column. The link table stores one row per pair. In RDF there are no rows: each pair is simply a triple, ex:P01 ex:hasPart ex:C01, and you add as many as you need.

2. What are the three parts of a triple? Write one about lead.

Subject, predicate, object. For example ex:C15 ex:containsMaterial ex:Lead . or ex:Lead ex:casNumber "7439-92-1" .

3. What is the difference between rdfs:subClassOf and rdf:type?

rdf:type says an individual belongs to a class (P01 is a Smartphone). rdfs:subClassOf relates two classes (every Smartphone is a Device). Combined, a reasoner concludes P01 is a Device.

4. If the graph does not say a product contains mercury, does that mean it does not?

No. Under the open-world assumption, missing information is unknown. SQL works the other way: a row that is not there is treated as false. To state “contains no mercury” in RDF you have to say it explicitly.

5. Why did the bill with 99 monitors save nothing at all?

All inserts ran in one transaction. When the stock check failed, the transaction rolled back, so even the valid phone line and the bill header were undone. That keeps the database consistent.
