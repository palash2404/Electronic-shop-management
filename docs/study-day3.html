Part 2: SHACL, the day 3 topic

~105 min
~25 min · Validating RDF Data, chapter 5, sections 5.1 to 5.6
  • Shape: a set of rules for one kind of node.
  • Target: which nodes the shape checks, e.g. sh:targetClass eshop:Product.
  • Property shape: rules for one property, found through sh:path.
  • Validation report: the output. It lists the node, the property, the bad value and a message.

Compare with day 1: a shape does the job of CHECK, NOT NULL and FOREIGN KEY in sql/schema.sql.

~20 min · graph/shapes.ttl, ProductShape · reference: SHACL spec, section 4

Find one example of each in ProductShape and say in your own words what it checks:

  • sh:minCount / sh:maxCount: how many values.
  • sh:datatype: the type of a value.
  • sh:minInclusive: a number range.
  • sh:in: a fixed list of allowed values.
  • sh:pattern: a regular expression (see MaterialShape).
  • sh:class: the linked thing must exist and be of that class.

Most important one in part 2. The core constraints look at one node and its direct values. A rule that follows a path through the graph (product → part → material) needs SPARQL.

Check yourself

Write your answers in NOTES.md in the repo first, then open each one to compare.

1. Why is there a node called ex:P01_C25, when ex:P01 eshop:hasPart ex:C25 already exists?

The direct triple says the phone has that camera module, but it cannot say how many. A triple has no room for a fourth value. The extra node stands for “this use of C25 in P01” and carries eshop:quantity 3. The direct triple is kept as well because it makes path queries short.

2. No product in data.ttl is typed as eshop:HazardousProduct. How does the reasoner find 16?

Two rules in the ontology. The property chain says: if a product has a part and the part contains a material, the product contains that material. The class definition says: a product that contains some hazardous material is a HazardousProduct. The reasoner applies both and adds the new triples.

3. What is the difference between OWL and SHACL? Which one complains when a product has no price?

OWL describes meaning and lets a reasoner add facts. SHACL checks facts and reports problems. Only SHACL complains about the missing price. OWL works under the open-world assumption, so a missing price is just unknown, not an error. SHACL treats the graph as complete, like a database constraint.

4. If containsMaterial had rdfs:domain eshop:Component, what would the reasoner conclude about ex:P01?

That ex:P01 is a Component. After the property chain runs, P01 contains materials, and a domain says “whatever has this property is a Component”. OWL does not reject the data, it draws a conclusion from it. To reject data you need SHACL.

5. Why does the “new products must not contain RoHS materials” rule need sh:sparql?

The material is two links away from the product: product → component → material, and the rule also looks at the material's regulation text. Core constraints such as sh:minCount or sh:in check a node's own values. Combining a condition on the product with a condition on something further along a path is easiest in a SPARQL query.

6. The shop data has one warning and is still reported as VALID. Why?

The rule for a missing CAS number has sh:severity sh:Warning. kg/validate.py only fails on findings with severity Violation. Aluminosilicate glass is a mixture with no single CAS number, so a hard failure would be wrong, but it is still worth showing.
